=== TASK 4 FINDINGS (2026-08-18) ===

1. Replay works. After a power cycle with the stored value = Main Out, Schwung
   emitted 37 12 02 at f866 and 37 14 01 at f867 — consecutive frames, one
   message per frame, identical in PRE and POSThw (so both reached hardware),
   and well after Move's own boot asserts at f3/f4/f30.

2. 37 12 bit0 preserved. Move asserted 37 12 00 at f4; our replay sent 37 12 02
   — bit1 set, bit0 untouched. The preservation logic works as designed.

3. Stored value not clobbered. usbc_out_state still read 1 after the boot.

4. Emission is deferred, not immediate. The replay is armed ~5 s in but landed
   at frame 866, because the emitter refuses while MIDI_OUT lacks a contiguous
   free run — which it does during Move's boot LED storm. This is the
   refuse-and-retry path working rather than corrupting. Expected behaviour.

5. Move's own Settings screen still reads "Mic" after the replay. Move does not
   adopt the value into its UI state. Evidence that it never persists the
   setting at all:
     - /data/UserData/settings/Settings.json has no corresponding key, and its
       mtime (08:31) predates the user changing the setting that day.
     - The Move binary instantiates the dialog as
       ListViewDelegate<UsbAudioOutputSourceDelegate, NullTransactionPolicy>
       — no persistence transaction, unlike settings that do persist.
     - Binary strings present: "USB-C Audio Out", "Change USB audio output
       source", UsbAudioOutputSourceDialog, UsbAudioOutputSourceDelegate.
   Consequence: Move's screen cannot be made to agree without driving its
   internal UI state, which is explicitly out of scope. This is what makes a
   Schwung-side "Persist USB-C Out" row worth building: with Move's screen
   showing a stale value, there is otherwise no honest place to read the truth.

6. UX trap to document: opening Move's menu shows "Mic" even when the hardware
   is on Main Out. Selecting "Main Out" there is harmless. Selecting "Mic" —
   believing it is a no-op — actually switches it off.

7. VERIFIED END TO END: with the stored value = Main Out, after a power cycle
   and without touching Move's menu, a connected computer receives main out.
   Confirmed by the user. Move's screen read "Mic" at the same time, which
   makes the cosmetic mismatch in (5) the only remaining gap — the audio path
   itself is correct.
